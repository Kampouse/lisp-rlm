## TS dialect pitfalls (each cost a red; probed via /tmp/bsprobe)

1. **Loop-carried u128-string mutation dies silently**: when 2+ string
   `let`s interlock through a loop (`lo,hi <- mid <- (lo+hi)`), writes
   stop sticking after iteration 1 — loop stalls, no trap. Unroll into
   unique-named `const` stages (`_bsearch_stages()`), same medicine as
   the lisp `let*` chain. Single-variable mutation + i32 counters work.
2. **3-arg muldiv is the free fn `u128MulDiv(a,b,d)`** — namespace
   member `u128.mulDiv` does NOT exist (silently lowers to nonexistent
   `u128/mul_div`).
3. u128 predicates are real bools; `?? "0"` for missing storage;
   exports use underscores (`get_paid`); scenario `manifest` is a
   comma-separated string.

## PITFALL: stale `state.bin` compounds additive ledgers

`near-mock scenario` **loads `state.bin` if present** and writes it at
the end. The splitters credit `paid:<who>` **additively**, so every
ad-hoc rerun inflates the expected `paid` assert by a growing multiple
(×2, ×3, …). The Rust test harness auto-zeroes state (`setup()` writes
`b""`), ad-hoc CLI runs do NOT.

Before any ad-hoc rerun of a scenario with cumulative asserts:

```
rm scen/*/state.bin   # or: : > scen/<name>/state.bin
```

Symptom if you forget: asserts fail with `paid:trader=K×expected`
while `get-split` (pure function of pinned inputs) still passes
exactly. The receipt DAG itself is fine — execute-once memoization
works; trace shows each `onK` firing once and outs summing exactly to
the pin.
